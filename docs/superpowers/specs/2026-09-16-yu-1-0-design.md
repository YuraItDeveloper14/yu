# Yu 1.0 — design

**Date:** 2026-09-16 · **Milestone:** 5b · **Status:** design approved by Yurii

## Goal

Yu 1.0.0: one version that the command line and the Studio both report; `yu` for Windows, Linux
and macOS that a person can download without Rust, with checksums; a repository page that explains
the project; the files a contributor looks for; a site that sends security headers; and an
accessibility check in CI.

## Who it is for

- Someone who wants `yu` on their computer and has never installed Rust.
- A visitor of the GitHub page deciding whether the project is alive and careful.
- A contributor who wants to know how to build it, test it and report a problem.

## Version

- `[workspace.package] version = "1.0.0"`. `yu --version` already prints `yu` and the crate
  version, so it prints `yu 1.0.0`; a CLI test checks it prints the workspace version.
- The core's `names()` JSON gains `"version"`. The Studio's status bar shows `Yu 1.0.0` as a link to
  the releases page. A browser test compares that text with the version in `Cargo.toml`.
- `CHANGELOG.md` in the Keep a Changelog form: one `1.0.0` section, dated the day the tag is pushed,
  listing what milestones 1–5 delivered by area (language, drawing, Studio, book, tools). Ukrainian
  first, then the same list in English.

## Release

`.github/workflows/release.yml` runs on a pushed tag `v*`, on `workflow_dispatch`, and on pull
requests that change the workflow itself, so the builds are proven before a tag exists.

| Runner | Target | File |
|---|---|---|
| `windows-latest` | `x86_64-pc-windows-msvc` | `yu-windows-x64.zip` |
| `ubuntu-latest` | `x86_64-unknown-linux-musl`, a static binary for any distribution | `yu-linux-x64.tar.gz` |
| `macos-latest` | `aarch64-apple-darwin` and `x86_64-apple-darwin`, joined with `lipo` | `yu-macos.tar.gz` |

- Each archive holds `yu` (`yu.exe` on Windows), `README.md`, `LICENSE` and `examples/`.
- Before packing, each job runs its binary: `yu --version` must print `yu` and the workspace
  version, and `yu examples/hello.yu` must print exactly `examples/hello.out`. On macOS,
  `lipo -archs` must list both `x86_64` and `arm64`.
- File names carry no version, so the README's `releases/latest/download/<file>` links stay right
  after every release.
- On a tag, a first step checks that the tag is `v` followed by the workspace version; a mismatch
  stops the run before anything is built.
- The `publish` job runs only for tags, with `contents: write`. It downloads the three archives,
  writes `SHA256SUMS.txt`, takes this version's section of `CHANGELOG.md` as the notes, and creates
  the release with `gh release create`.
- The binaries are not signed: signing costs money. Windows SmartScreen and macOS Gatekeeper will
  warn, and the README says how to open `yu` anyway.
- After publishing: `gh release download v1.0.0`, `sha256sum -c SHA256SUMS.txt`, and the Windows
  binary runs on Yurii's computer and prints `yu 1.0.0`.

## README

- Badges under the title: CI, the latest release, the licence, the site.
- A «Встановити» section: the three downloads as `releases/latest/download/` links, how to check
  a file against `SHA256SUMS.txt`, how to open an unsigned binary on Windows and macOS, and
  `cargo install --git https://github.com/YuraItDeveloper14/yu --tag v1.0.0 yu-cli` for people with
  Rust.
- «Далі: реліз v1.0.» becomes the plan after 1.0: v1.1 with frame animation, dictionaries and
  values inside text.

## Repository page

- Website: `https://yu-lang.vercel.app`.
- Description: "Yu — a programming language that speaks Ukrainian: bilingual keywords, Python-style
  blocks, friendly errors, turtle drawing, a browser studio and a book. Written in Rust."
- Topics: the six there are, plus `webassembly`, `turtle-graphics`, `beginners`, `learn-to-code`,
  `ide`, `typescript`.
- Private vulnerability reporting switched on.
- A social preview, `docs/social-preview.png` (1280×640): the logo, the name, one line and a short

  Settings → General → Social preview.

## Community files

Ukrainian first, then English, in each file.

- `CONTRIBUTING.md`: what to install (Rust from `rust-toolchain.toml`, Node 24), every check CI runs
  and how to run it locally, how a new word enters the language (its library entry, then rebuilding
  the book), and how commits and pull requests are written.
- `SECURITY.md`: supported versions (1.x); how to report privately through the Security tab; what
  the Studio does with a program (it runs in the reader's browser and is sent nowhere).
- `CODE_OF_CONDUCT.md`: short rules in the project's own words. Private reports also go through the
  Security tab: it is GitHub's only private channel that needs no email address, and the files
  publish none.
- `.github/ISSUE_TEMPLATE/bug.yml` (where: command line, Studio or book; the program; what was
  expected; what happened; the version), `idea.yml`, and `config.yml` that links to the book and the
  Studio.
- `.github/pull_request_template.md`: what and why, and the checks that were run.
- `.github/dependabot.yml`: `cargo` at `/`, `npm` at `/studio`, `github-actions` at `/`, weekly,
  with npm and actions updates grouped into one pull request each.
- The workflows use the newest majors of the actions, which run on Node 24:
  `actions/checkout@v7`, `actions/setup-node@v7`, `actions/upload-artifact@v7`,
  `actions/download-artifact@v8`.

## Site security headers

`studio/public/vercel.json` sends these with COOP and COEP on every path:

```
Content-Security-Policy: default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self'; worker-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()
X-Frame-Options: DENY
Cross-Origin-Resource-Policy: same-origin
```

- Each exception has a reason: `'wasm-unsafe-eval'` compiles the core; inline styles come from
  CodeMirror, which writes its styles at run time, and from a drawing's SVG, which carries its own
  `<style>`; `data:` and `blob:` images are the library's pictures and saving a picture as PNG.
- Vercel already sends HSTS, so it is not repeated.
- The book's two inline scripts (the saved theme, and the language jump at `/book/`) move to files
  in `studio/public/`, so no page has an inline script and the policy needs no hashes.
- `vite preview` takes its headers from `public/vercel.json`, so every browser test, locally and in
  CI, runs under the policy the site sends. `vite dev` keeps only COOP and COEP: hot reload needs a
  websocket.
- The browser tests fail on any `securitypolicyviolation` event, and one test checks that the
  headers are served.

## Accessibility

- `@axe-core/playwright` 4.13.0 checks the WCAG 2.0 and 2.1 A and AA rules on: the Studio in the
  dark and the light theme; a book chapter in both themes; the reference chapter; a chapter at
  phone width.
- Every violation is fixed. If a rule fires inside a third-party widget and cannot be fixed from
  outside, the test excludes that element with a comment that says why.

## Out of scope

- Code signing and notarisation.
- crates.io, winget, Homebrew and other package managers.
- ARM builds for Windows and Linux.

## Order

One pull request, in this order: version and changelog; the release workflow; the README; community
files and newer actions; security headers; accessibility. Then: merge, deploy, check the headers on
the live site, push the tag `v1.0.0`, watch the release, download and verify it, and apply the
repository page settings.
